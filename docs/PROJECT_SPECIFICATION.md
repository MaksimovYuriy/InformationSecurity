# Описание проекта и технические спецификации

Этот документ — основной источник технического контекста перед выполнением задач. Он описывает актуальную реализацию, контракты и принятые технические решения. Обновляется вместе с изменениями кода и спецификаций. Планы будущих возможностей явно отделяются от работающего поведения.

## Назначение и состояние

Цель — служба проверки безопасности облачного хранилища: получение конфигурации, выполнение 6–10 правил, оценка опасности, рекомендации и подтверждение исправлений. ИИ-агент входит в проект и добавляется последним.

Завершены итерации 1 и 2: локальное окружение и консольный сценарий на фиксированных демонстрационных данных. Для итерации 3 выбран VK Cloud Object Storage (S3), московский endpoint `https://hb.ru-msk.vkcloud-storage.ru`. По сообщению пользователя созданы учебный бакет, тестовые файлы и учётные данные; 22.11.2026 реальными CLI-запусками подтверждены подключение и получение одного бакета. Итерация 3 принята пользователем как завершённая с явно согласованным исключением: минимальность прав аудитора и отдельное сопоставление списка с кабинетом не подтверждены и не блокируют дальнейшую разработку. Эти проверки не считаются выполненными. Итерация 4 завершена: реализованы сбор и нормализация настроек бакета, безопасное сохранение и чтение снимков; реальный запуск проверен. Интерпретации политик и движка правил пока нет. Окончательные правила не выбраны. Отдельная VM потребуется при серверном развёртывании в итерации 9.

## Стек и запуск

- Python 3.12+, boto3 1.35.99 для облачного профиля. Проверенный набор прямых и транзитивных зависимостей закреплён в `requirements.txt`; установка: `.venv/bin/python -m pip install -r requirements.txt`.
- Исходники в `src`, тесты — `unittest` в `tests`.
- Версия приложения: `0.1.0`, определена в `src/cloud_audit/__init__.py` и метаданных `pyproject.toml`.
- Проверенный способ запуска из корня: `PYTHONPATH=src .venv/bin/python -m cloud_audit ...`.
- Установочная консольная точка входа в метаданных: `cloud-audit = cloud_audit.cli:main`; установка пакета не входит в выполненные проверки.

## Архитектура и код

Зависимости направлены к внутренним слоям. CLI собирает конкретные реализации и передаёт их прикладным сервисам.

| Модуль | Назначение |
|---|---|
| `domain/settings.py` | Неизменяемая модель `Settings` |
| `domain/audit.py` | Неизменяемые модели `Resource`, `RuleResult`, `AuditReport` |
| `application/environment.py` | `EnvironmentService`, интерфейс `StateStorage`, результат `EnvironmentReport` |
| `application/audit.py` | `AuditService`, интерфейсы `StorageProvider` и `ReportRepository`, ошибка `AuditError` |
| `infrastructure/configuration.py` | Чтение и валидация переменных окружения, `ConfigurationError` |
| `infrastructure/storage.py` | Подготовка локальных каталогов через `LocalStateStorage` |
| `infrastructure/s3.py` | `S3Provider`: список бакетов, пагинация, ошибки и делегирование сбора конфигурации |
| `domain/snapshot.py` | Модели `ConfigurationObservation` и `ConfigurationSnapshot`, охват и статусы данных |
| `application/snapshot.py` | `SnapshotService`, интерфейсы `ConfigurationCollector` и `SnapshotRepository` |
| `infrastructure/s3_configuration.py` | Восемь запросов чтения настроек S3 и нормализация |
| `infrastructure/snapshots.py`, `snapshot_schema.py` | Хранение снимков, проверка схемы и срока хранения |
| `infrastructure/demo.py` | `DemoProvider`: фиксированные ресурсы и имитация результата |
| `infrastructure/reports.py` | `JsonReportRepository`: локальное сохранение и чтение отчётов |
| `cli.py`, `__main__.py` | Аргументы, сборка зависимостей, вывод и завершение процесса |

`StorageProvider` предоставляет `connect()`, `resources()` и `preview(resource, rules)`. `ReportRepository` предоставляет `save(report)` и `get(report_id)`. `StateStorage` предоставляет `prepare()`. `ConfigurationCollector` задаёт режим `mode` и `collect(resource)`; `SnapshotRepository` — `save(snapshot)` и `get(snapshot_id)`.

`StorageProvider` также задаёт `mode`, `audit_available` и `connection_message`; сервис не привязан к demo. Для VK Cloud аудит отклоняется до обращения к ресурсу и сохранения отчёта. Интерфейс `preview` остаётся демонстрационным каркасом, а не движком правил.

## Модели данных

- `Settings`: `environment: str`, `log_level: str`, `state_dir: Path`.
- `Resource`: `id: str`, `name: str`.
- `RuleResult`: `rule_id: str`, `status: str`, `explanation: str`.
- `AuditReport`: `id: str`, `mode: str`, `resource: Resource`, `results: tuple[RuleResult, ...]`.
- `EnvironmentReport`: `status: str`, `environment: str`, `log_level: str`.

При JSON-сериализации кортеж результатов становится массивом. Идентификатор отчёта — `uuid4().hex`: 32 шестнадцатеричных символа в нижнем регистре. Время запуска, оценки риска и доказательства пока в модель не включены.

## Контракт CLI

| Команда | Параметры и поведение |
|---|---|
| `--version` | Версия без подготовки каталогов |
| `check` | Подготовка окружения; JSON с `version`, `status`, `environment`, `log_level` |
| `connection` | demo: имитация; vk: авторизованный ListBuckets |
| `resources` | demo: фиксированные ресурсы; vk: реальные бакеты с пагинацией |
| `audit` | Обязательный `--resource`; необязательный `--rules` с одним или несколькими значениями; сохранение и вывод отчёта |
| `report REPORT_ID` | Чтение ранее сохранённого отчёта |
| `collect` | Обязательный `--resource`, профиль только `vk` (по умолчанию); сбор и сохранение конфигурации одного бакета |
| `snapshot SNAPSHOT_ID` | Чтение сохранённой конфигурации без облачных ключей и сетевых запросов |

Для `connection`, `resources`, `audit` доступен `--profile demo|vk`, значение по умолчанию — `demo`. Облачный `audit --profile vk` пока возвращает код 2, отчёт не создаётся. Для всех подкоманд, кроме `check`, доступен `--format json|text`, по умолчанию `json`. Текстовый формат — заголовок DEMO либо VK CLOUD согласно режиму и форматированный JSON. Заголовок VK явно сообщает об отсутствии оценки безопасности; для `collect` и `snapshot` также обозначен охват конфигурации бакета.

Демонстрационные ресурсы: `demo-public` и `demo-private`. Единственный сценарий — `demo-public-read`, он выбирается при отсутствии `--rules`. Неизвестные сценарии отклоняются, повторы исключаются. Результат всегда имеет статус `simulated`, а отчёт — `mode: demo`: это не заключение о безопасности.

Коды завершения:

- `0`: команда выполнена; для снимков — все запрошенные настройки доступны либо явно отсутствуют (`complete_for_scope`). Не означает отсутствие нарушений.
- `1`: ошибка доступа к локальному состоянию.
- `2`: неверные аргументы, конфигурация, ресурс, правило, идентификатор или недоступный/некорректный отчёт; ошибка облачной авторизации, доступа, сети, API или ответа.

Ошибки выводятся в stderr без traceback для предусмотренных случаев. Для `collect` и `snapshot` дополнительно используется код `3`: снимок сохранён/прочитан, но часть запрошенных данных недоступна (`partial`).

Все команды после разбора аргументов, кроме `--version` и справки, подготавливают каталоги состояния.

## Конфигурация и безопасность

| Переменная | По умолчанию | Допустимые значения |
|---|---|---|
| `CLOUD_AUDIT_ENV` | `development` | `development`, `test`, `production` |
| `CLOUD_AUDIT_LOG_LEVEL` | `INFO` | `DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL` |
| `CLOUD_AUDIT_STATE_DIR` | `.state` | Непустой путь к выделенному каталогу приложения |

Приложение читает окружение процесса, автоматически `.env` не загружает. Инструкция доверенной загрузки через shell — в README. `.env.example` содержит только безопасные значения; `.env` и его варианты исключены из Git.

Для `--profile vk` используются `CLOUD_AUDIT_S3_ENDPOINT_URL` (по умолчанию `https://hb.ru-msk.vkcloud-storage.ru`), `CLOUD_AUDIT_S3_REGION` (регион подписи, по умолчанию `us-east-1`), обязательные `AWS_ACCESS_KEY_ID` и `AWS_SECRET_ACCESS_KEY`. Ключи исключены из repr модели `S3Settings`. Endpoint должен быть HTTPS без credentials, query, fragment и пути (кроме `/`), порт 443 или не указан. Учётные данные передаются SDK явно; не выполняется поиск ключей через metadata или профили AWS. Файл `.env` автоматически не читается; при проверке значения загружались вспомогательным процессом локально и не выводились агенту.

Конфигурация подключения общая для нескольких бакетов, имя бакета в окружении не задаётся. Целевой ресурс выбирается `audit --resource`, облачный аудит пока не реализован. Пакетный аудит всех бакетов также не реализован.

SDK использует Signature V4, path-style, тайм-ауты 5/10 секунд и до трёх попыток в standard mode. `ListBuckets` вызывается без фильтра по имени, continuation token обрабатывается до конца, дубликаты удаляются, ошибочная пагинация отклоняется. Неполный результат при ошибке не возвращается. Отказ доступа не превращается в пустой список. Сообщения SDK не выводятся, SDK-логгеры ограничены уровнем CRITICAL даже при DEBUG приложения. Адаптер не выполняет операций записи. Успешное подключение не доказывает отсутствие прав записи у ключа.

Каталоги состояния, `data` и `logs` создаются с правами `0700`; у существующих этих каталогов права также изменяются на `0700`. Проверяется возможность записи. Нельзя указывать общий каталог пользователя как корень состояния.

Отчёты хранятся в `STATE_DIR/data/REPORT_ID.json`. Запись использует временный файл с правами `0600` и атомарную замену. Идентификатор проверяется до построения пути. При чтении проверяются структура, совпадение идентификатора и режим `demo`; полноценная версия схемы пока не введена.

Логирование — стандартный `logging` в stderr. Секреты запрещены в коде, Git, журналах, отчётах и контексте ИИ.


## Снимок конфигурации — итерация 4

`ConfigurationSnapshot`: `id` (uuid4 hex), `schema_version: 1`, `provider`, `resource`, `collected_at` (ISO 8601 с UTC, начало сбора), `scope: bucket_configuration_only`, `limitations`, `collection_status` и кортеж `observations`. `ConfigurationObservation`: `name`, `source` (исходный метод API), `status`, `data` (нормализованный JSON-словарь либо `null`), `reason` (безопасная причина либо `null`).

Собираются восемь настроек: `bucket_acl`, `bucket_policy`, `public_access_block`, `ownership_controls`, `versioning`, `logging`, `encryption`, `object_lock`. В ACL хранятся идентификатор владельца и гранты (тип/идентификатор субъекта/разрешение); политика сохраняется JSON-документом с исходными условиями без интерпретации. Остальные настройки нормализуются в независимые словари с именами полей snake_case. Неизвестный MFADelete — `null`; отсутствие Status в успешном GetBucketVersioning означает Disabled согласно контракту S3. Снимки могут включать идентификаторы, ARN и политику ресурса; ключи и SDK ResponseMetadata в них не включаются.

Статусы данных: `available`, `absent`, `access_denied`, `unsupported`, `error`. Отсутствующая настройка определяется только специальным кодом API либо документированным успешным пустым ответом. Неоднозначный 404 остаётся ошибкой, NoSuchBucket прерывает сбор. Ошибки авторизации также прерывают сбор без записи. Остальные ошибки фиксируются в соответствующем поле, остальные настройки продолжают собираться. `complete_for_scope` устанавливается только при available/absent для всех восьми настроек; иначе `partial`. Это статусы сбора данных, а не будущие статусы нарушений.

Охват: только настройки конкретного бакета, прямые Get-запросы без ListObjects и GetObject. ACL объектов, содержимое файлов и настройки аккаунта не собираются; запросы последовательны, атомарность состояния облака не гарантируется. Ограничения всегда включают `object_acl_not_collected`, `object_contents_not_collected`, `account_controls_not_collected`, `security_not_assessed`, `sequential_requests_not_atomic`. Неприменимость объектных проверок этому режиму отражена охватом, а не результатами о безопасности объектов.

Хранение: `STATE_DIR/data/snapshots/ID.json`, каталог 0700, файлы 0600, временный файл + fsync + атомарная замена. Максимум 2 МиБ; при чтении и сохранении проверяются идентификатор, версия, структура, источники, статусы, формы данных и согласованность полноты. Символические ссылки на файлы отклоняются. Срок — 7 суток от начала сбора: просроченные снимки не выдаются, корректные просроченные файлы удаляются при следующем сохранении. Фонового удаления нет; повреждённые/посторонние файлы не удаляются автоматически. CLI snapshot работает без ключей. Подробные поля и сценарии — в `docs/ITERATION_04.md`.

## Проверки и ограничения

Команда: `PYTHONPATH=src .venv/bin/python -m unittest discover -s tests -v`.

Проходят 28 тестовых методов: 15 прежних и 13 новых для итерации 4. Новые тесты покрывают нормализацию восьми настроек, сохранение условий политики, различение отсутствия/отказа доступа/неподдерживаемого API/сети/лимитов/повреждённого ответа, отсутствие ресурса и ошибки авторизации, явный охват, снимок между процессами без ключей, TTL, права файлов, проверку схемы и сбой атомарной записи. TDD подтверждён ожидаемыми падениями до добавления сервиса и CLI; дополнительные проверки выявили и помогли исправить трактовку MFADelete и проверку вложенных данных.

Реальные `connection --profile vk` и `resources --profile vk` подтвердили подключение и один бакет. Реальный `collect` и чтение сохранённого снимка прошли; независимые запросы ACL и версионирования совпали с нормализованными значениями. На учебном бакете ACL, Ownership Controls и версионирование — `available`; политика и Object Lock — `absent`; Block Public Access, журналирование и шифрование через соответствующие S3 API — `unsupported`. Снимок имеет статус `partial` и код 3, что корректно отражает ограничения сбора. Неподдерживаемый API не доказывает отсутствие защиты провайдера. Положительные ответы ряда настроек проверены тестовыми данными и не утверждаются для реального стенда.

Минимальность прав аккаунта, ACL отдельных объектов, фактический анонимный доступ и безопасность политик пока не подтверждаются. Ограничения завершения итерации 3 приняты пользователем. Протоколы: `docs/ITERATION_03.md`, `docs/ITERATION_04.md`.
