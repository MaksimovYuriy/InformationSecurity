# Проверка корректности перед итерацией 6

Дата: 22.11.2026. Проверены спецификация, слои приложения, движок, первое правило, сериализация, конфигурация и имеющиеся сценарии тестирования. Это проверка текущего объёма реализации, а не независимая сертификация безопасности или полный анализ всех возможных политик.

## Исходное состояние

Все 41 прежний тест прошли. Подключение к VK Cloud, сбор конфигурации, сохранение и чтение снимков/отчётов и проверка версионирования имели воспроизводимые сценарии. SDK находится в инфраструктуре, правила не зависят от boto3. Неполные данные явно отличаются от отсутствия нарушения. Demo не выдаётся за реальный аудит.

Подтверждены ограничения: минимальность прав аккаунта не проверена и ранее принята пользователем; конфигурация трёх настроек через S3 API на стенде недоступна; фактические внешние/избыточные права ещё не проверяются. Контекст желаемых прав и допустимых аккаунтов не считается доказательством реальных разрешений.

## Найдено и исправлено через падающие тесты

1. Локальный снимок с датой далеко в будущем обходил семидневный срок хранения. Теперь дата более чем на 5 минут впереди локальных часов отклоняется.
2. Проверка сохранённого отчёта допускала противоречие `passed` и доказательства Disabled для правила версионирования. Теперь источник, распознанное значение и статус согласуются с базовой политикой.

Дополнительно проверено, что файл отчёта с некорректным UTF-8 уже обрабатывался контролируемой ошибкой, а не traceback. Эта проверка не потребовала исправления.

После исправлений прошли 44 теста. В итерации 6 аналогичная проверка согласованности добавлена для подтверждённых анонимных операций: в сохранённом отчёте необходима положительная unsigned-проба с HTTP 2xx.

## Оценка

В пределах итераций 1–5 основные сценарии подтверждены, обнаруженные ошибки валидации исправлены. Проверки структуры обеспечивают согласованность, но не криптографическую подлинность локальных файлов: пользователь с правом записи может согласованно изменить данные. Закрытые права файлов остаются обязательными.

Утверждать, что приложение уже полностью проверяет безопасность бакета, было бы неверно: до итерации 6 было одно правило, сбор не включал ACL объектов, поддерживаемые API провайдера ограничены. После итерации 6 охват по-прежнему ограничен выбранными объектами, конечным набором операций и поддерживаемой частью политик. Подтверждённый отрицательный запрос относится к конкретному объекту, операции, моменту и контексту запроса.

Итоговый регрессионный прогон с итерацией 6: 70 тестов успешно. Полный протокол реальных испытаний — [ITERATION_06.md](ITERATION_06.md).
