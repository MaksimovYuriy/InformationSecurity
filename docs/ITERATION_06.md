Сценарий «закрыто → открыто → закрыто» подтверждён на VK Cloud и завершён удалением временного стенда. Ограничения интерпретации политик и охвата сохранены явно.

## Реализация

- `domain/public_access.py`: независимый анализ политики/ACL, четыре операции, ограничения и доказательства. [Карточки](rules/ANONYMOUS_ACCESS.md).
- `application/rule_registry.py`: текущий набор — версионирование плюс anonymous-read/list/write/delete. Добавление правил не требует изменения RuleEngine.
- `domain/snapshot.py`: CollectionOptions (до 20 уникальных явно выбранных ключей) и расширенный охват.
- `infrastructure/s3_configuration.py`: GetObjectAcl только для переданных ключей, без обхода всех объектов.
- `infrastructure/anonymous.py`: отдельный boto3-клиент с UNSIGNED, без аутентификации; чтение/список и отдельно включаемые пробы записи/удаления.
- `scripts/verify_public_access.py`: контролируемый стенд с новым случайно названным бакетом и одним искусственным файлом. Не изменяет существующие бакеты. Включает только публичные чтение/список, не публичную запись.

Новая конфигурация представлена снимками v2; v1 продолжает читаться. В v2 есть object_keys, дополнительные наблюдения object_acl:KEY и при включении проб — anonymous_list, anonymous_read:KEY, anonymous_write/delete. Охват — bucket_configuration_only либо bucket_and_selected_objects. Общая восьмёрка настроек бакета сохраняется. Все новые отчёты имеют schema_version=2, старые отчёты v1 читаются. В Finding добавлены limitations, в SecurityReport — object_keys; ограничения собираются также на уровне отчёта.

Статус not_found отличает отсутствующий выбранный объект от отказа доступа. Проба хранит доступное доказательство результата запроса в data.outcome (allowed/denied/not_found/error), http_status и checked_at, а не содержимое файла. Ошибка пробы делает снимок partial. Положительное доказательство не стирается при ошибке уборки временных объектов; cleanup_failed отражается и в отчёте, оценка становится incomplete.

Запросы выполняются только при --probe-anonymous. По умолчанию проверки доступа анализируют конфигурацию. Известное публичное разрешение без подтверждения — potential_risk; положительная проба — confirmed_violation. Denied не является глобальным доказательством закрытости. Условия политик и Not* пока не вычисляются, возвращаются ограничения/неопределённость. Избыточные права конкретных пользователей и разрешённые внешние аккаунты остаются будущими правилами итерации 7.

## CLI

```bash
# Только конфигурационный анализ выбранных искусственных объектов:
PYTHONPATH=src .venv/bin/python -m cloud_audit audit --profile vk --resource BUCKET_NAME --objects test.txt
# Независимо проверить чтение и список без учётных данных:
PYTHONPATH=src .venv/bin/python -m cloud_audit audit --profile vk --resource BUCKET_NAME --objects test.txt --probe-anonymous
# Проверить только две операции:
PYTHONPATH=src .venv/bin/python -m cloud_audit audit --profile vk --resource BUCKET_NAME --objects test.txt --probe-anonymous --rules anonymous-read anonymous-list
# Офлайн-анализ сохранённого снимка сохраняет исходные метаданные проб, не повторяет сеть:
PYTHONPATH=src .venv/bin/python -m cloud_audit audit --profile vk --snapshot SNAPSHOT_ID
```

collect также принимает --objects и --probe-anonymous. Новые флаги запрещены для demo и --snapshot. Для записи/удаления нужен дополнительный явный --allow-write-probes; эти запросы затрагивают только генерируемые временные объекты, не выбранные пользовательские файлы. На учебном облаке публичные write/delete не включались; положительные и ошибочные сценарии этих проб проверены локально.

Для полного воспроизведения основного сценария после загрузки локального окружения:

```bash
PYTHONPATH=src .venv/bin/python scripts/verify_public_access.py --run-training-fixture
```

Команда создаёт новый бакет и на короткое время публикует только искусственный файл и список его бакета. После проверки удаляет политику, закрывает ACL и удаляет созданные файл/бакет. Уборка выполняется в finally, каждый шаг пробуется независимо; ошибки отражаются в итоговой сводке. Сводка сохраняется с правами 0600 в .state/data/fixture-UUID.json.

Коды CLI: 0 — выбранные правила оценены (могут быть нарушения), 3 — insufficient_data или ошибка уборки проб, 2 — ошибка входа/запроса, 1 — файлового доступа. Частичный снимок не мешает оценке правила, которому доступны все необходимые данные. Код 0 не означает «бакет безопасен».

## Проверки и ограничения

71 тест: прежние 41, три проверки предварительного ревью и 27 проверок итерации 6. Новые сценарии сначала падали на отсутствии модуля/CollectionOptions и неподдерживаемом охвате отчёта, затем реализованы до прохождения. Дополнительные тесты выявили необходимость запрета трогать ранее существовавшие версии проб, проверки подтверждающего runtime-доказательства и продолжения уборки после ошибки создания файла; исправления внесены до завершения.

Дополнительно исправлено необработанное исключение SDK ResponseParserError при повреждённом XML: оно не является BotoCoreError и теперь безопасно обрабатывается в чтении и пробах, без исходного ответа.

Покрыты разные операции ACL, безусловные запреты, несовпадающие ARN, маски, Ownership Controls, AuthenticatedUsers, неизвестные условия/Not*, положительные и отрицательные пробы, 404, недоступная политика, выбранные объекты, схема v2 и совместимость, отключённые по умолчанию мутации, условное создание, очистка версий и маркеров, отказ подготовки и ошибка уборки.

Ограничения: не полный IAM-интерпретатор; Condition и Not* не поддерживаются. Нет обхода всех объектов/версий, проверки access points и настроек аккаунта. Одна отрицательная проба не подтверждает закрытость всех контекстов. Public Access Block API на учебном endpoint не поддерживается; другие механизмы защиты провайдера не объявляются отсутствующими. Реальные положительные write/delete, сетевые сбои и отказ ACL проверены локально, не провоцировались в облаке. Минимальность прав аккаунта остаётся согласованным ограничением. История и автоматическое сравнение отчётов относятся к итерации 8.
