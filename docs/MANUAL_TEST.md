# Самостоятельный запуск

В текущей рабочей папке приложение уже установлено. Существующий `.env` автоматически читается из текущего каталога. Экспортировать ключи, создавать файл целей или определять shell-функцию для обычного запуска не нужно.

## Одна команда

Из корня проекта, заменив `my-training-bucket` реальным именем:

```bash
./cloud-audit scan --buckets my-training-bucket
```

Приложение само выполняет внешний этап без подписи, затем внутренний анализ, если в `.env` или окружении есть оба ключа, и сохраняет результат. По умолчанию ничего не загружает и не удаляет в проверяемом хранилище.

Несколько бакетов:

```bash
./cloud-audit scan --buckets bucket-one bucket-two
```

Все бакеты, видимые загруженному ключу:

```bash
./cloud-audit scan --all-buckets
```

Если не помнишь имя:

```bash
./cloud-audit resources --profile vk
```

## Только внешний этап

```bash
./cloud-audit scan --buckets my-training-bucket --external-only
```

Ключи игнорируются. Если List запрещён и имена файлов неизвестны, Get останется непроверенным. Для задания известных ключей отдельно каждому бакету есть необязательный `--targets` — пример в `scan-targets.example.json` и [описание](STAGED_SCAN.md).

## Запись и удаление — отдельное явное включение

Только для своего учебного бакета:

```bash
./cloud-audit scan --buckets my-training-bucket --mutation-buckets my-training-bucket
```

Эта команда создаёт собственные искусственные `_cloud-audit-probe/UUID/write.txt` и `delete.txt`. При наличии прав использует ключи для подготовки/проверки эффекта/уборки; проверочные PUT/DELETE остаются анонимными. Существующие пользовательские файлы для этих проб не выбираются. Для мутаций без ключей нужен отдельный `--allow-residue`, описанный в STAGED_SCAN.md.

На закрытом бакете ожидаются denied, а не allowed. Флаг не открывает настройки хранилища сам. Not_tested означает, что условия безопасной подготовки/уборки не выполнены. Cleanup=residue/unknown означает, что полная уборка не подтверждена; точные target сохранены в отчёте.

## Прочитать результат

Верхний `id` ответа — SCAN_ID общей сводки. Подставь его:

```bash
./cloud-audit scan-report SCAN_ID --format markdown
./cloud-audit scan-report SCAN_ID --format markdown --output report.md
```

Экспорт создаёт новый файл и не перезаписывает существующий. `internal_report_id` — отдельный отчёт бакета, его можно открыть через `./cloud-audit report INTERNAL_REPORT_ID --format text`.

Результаты находятся в CLOUD_AUDIT_STATE_DIR из конфигурации (по умолчанию `.state`). Код 0 означает выполнение выбранных проверок, а не отсутствие нарушений; 3 — неполный охват/анализ/уборку; 2 — ошибку аргументов/конфигурации/ID; 1 — локального состояния. Код последней команды: `echo $?`.

## Полный автоматический эксперимент — необязательно

```bash
.venv/bin/python scripts/verify_staged_scan.py --run-training-fixture
```

Этот скрипт сам создаёт три новых бакета, загружает искусственные файлы, временно открывает учебный доступ, проверяет операции и закрытие, затем удаляет созданные объекты/версии/бакеты. Для него нужны права создания/изменения/уборки стенда. Существующие бакеты не изменяет. Итог должен содержать success=true, cleanup_ok=true и код 0; иначе изучи summary_path и owned_buckets.

## Установка на другом компьютере — один раз

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt -e .
```

После этого `./cloud-audit ...` работает без активации окружения и без PYTHONPATH. Если предпочитаешь имя без `./`, активируй окружение один раз для терминала:

```bash
. .venv/bin/activate
cloud-audit scan --buckets my-training-bucket
```

Launcher не меняет текущий каталог: `.env` ищется там, откуда запущена команда. Для другого файла: `./cloud-audit --env-file /path/to/project.env scan --buckets my-training-bucket`. Чтобы использовать только переменные процесса: `./cloud-audit --no-env-file scan --buckets my-training-bucket`. Эти общие флаги идут перед подкомандой.

Переменные процесса приоритетнее `.env`, включая пустые значения. Поддерживаются однострочные KEY=value, `export KEY=value`, кавычки и комментарии; shell-команды и подстановки не выполняются. Необходимые пути указывай явно, `$HOME`/`${NAME}` не раскрываются. Ключи и содержимое `.env` не присылай в чат.
