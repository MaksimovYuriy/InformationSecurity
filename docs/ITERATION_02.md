# Итерация 2: консольный каркас

> Исторический протокол: названия модулей/тестов и команды приведены на момент этапа. После рефакторинга актуальные структура и запуск описаны в [карте документации](README.md), соответствие имён — в [итерации 10](ITERATION_10.md).

## Реализовано

- Команды `connection`, `resources`, `audit`, `report`; сохранены `check` и `--version`.
- Параметры профиля, целевого ресурса, набора правил и формата вывода.
- Демонстрационный адаптер с двумя фиксированными ресурсами; он не подключается к облаку и не выполняет настоящие проверки безопасности.
- Прикладной сервис зависит от интерфейсов провайдера и репозитория, а не от CLI или файлового хранилища.
- Минимальный JSON-репозиторий сохраняет отчёт между процессами; временный файл записывается с закрытыми правами и атомарно заменяет целевой.
- Идентификаторы отчётов валидируются, обращения через произвольные пути не допускаются.
- Ошибки запроса и файлового доступа возвращаются без traceback и вывода секретов.

## Проверка

Сначала добавлены сценарные тесты. До реализации основной сценарий упал из-за отсутствующей команды `connection`. После реализации все восемь тестов проходят: пять из первой итерации и три сценарных теста второй с дополнительными случаями неверных параметров.

Отдельно выполнен сквозной запуск в `.venv`: подключение к demo → список ресурсов → аудит demo-public → чтение сохранённого отчёта отдельным процессом в текстовом формате.

Команда полного прогона:

```bash
PYTHONPATH=src .venv/bin/python -m unittest discover -s tests -v
```

## Статус и ограничения

Итерация 2 завершена. Демонстрационный режим явно отмечен в JSON и текстовом выводе; результаты помечены `simulated`. Это проверка пользовательского сценария, а не движок правил. Облачный адаптер, реальные политики доступа и полноценная история аудита будут реализованы в следующих итерациях. Итерация 3 не начата.
