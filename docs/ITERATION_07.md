# Итерация 7: восемь правил и рекомендации

## Статус и результат

Завершена. Окончательный набор основной версии — [восемь обоснованных правил](rules/RULE_CATALOG.md). К пяти прежним добавлены внешний именованный доступ, избыточные явные права и отключение ACL как мера против случайной публикации. Для всех правил есть карточки угроз, источников, алгоритмов, риска, исключений, исправления и подтверждения. Рекомендации детерминированы, ИИ не используется.

Журналирование, шифрование и другие неподдерживаемые либо не обоснованные для обязательного набора механизмы не объявляются отсутствующими. Объём не расширялся до полного IAM-анализатора.

## Архитектура

- `domain/access_grants.py`: инвентарь явных разрешений/запретов из текущих снимков. Зависимостей от SDK, файлов и CLI нет.
- `domain/governance_rules.py`: ExternalAccessRule, ExcessPermissionsRule, AclDisabledRule с общим контрактом SecurityRule.
- Реестр расширен до восьми без изменения RuleEngine и механизма исключений.
- AuditPolicy дополнена необязательным trusted_project_ids. required_controls поддерживает acl_disabled, операции baseline — write_acl. Дубликаты subject в required_permissions отклоняются. Пустой operations у конкретного субъекта — явное отсутствие необходимых прав; пустой required_permissions целиком — отсутствующая модель.
- Пример `audit-policy.example.json` дополнен полем доверенных проектов. Его пустые списки не являются заполненной пользовательской baseline.
- Схемы снимков не менялись: используются уже собранные policy/ACL/ownership. Отчёты v1/v2 читаются совместимо, optional trusted_project_ids восстанавливается пустым при отсутствии. Для bucket-acl-disabled дополнена проверка согласованности результата с доказательством и базовой политикой.

## Контекст политики

```json
{
  "data_sensitivity": "unknown",
  "trusted_project_ids": ["mcs-example-own-project"],
  "allowed_external_accounts": ["mcs-example-partner-project"],
  "required_controls": ["versioning"],
  "required_permissions": [
    {"subject": "arn:aws:iam::mcs-example-partner-project:user/example-app", "operations": ["read"]}
  ],
  "exceptions": []
}
```

Это фиктивные идентификаторы, не готовые настройки пользователя. trusted_project_ids — собственные/доверенные проекты из модели доступа VK Cloud, не Access Key ID. allowed_external_accounts допускает точный субъект либо проект и его user ARN. Для ACL CanonicalUser используются наблюдаемые идентификаторы. Владельца объекта нельзя автоматически приравнять к доверенному владельцу бакета.

Модель необходимых операций задаётся пользователем, а не копируется из текущих грантов. Внутренние неявные права, ненаблюдаемый субъект или неизвестная принадлежность проекта не позволяют уверенно утверждать least privilege. unknown/insufficient_data — нормальный результат отсутствующего контекста.

## Ограничения и следующий этап

Полный IAM, неявные внутренние права, Condition/Not*, неподдерживаемые действия, невыбранные объекты/версии и фактический вход внешних субъектов не анализируются. Potential_risk именованных грантов не выдаётся за подтверждённый внешний сеанс. Отключение ACL не запрещает публичные политики и может требовать миграции приложений; изменений аудитор не делает. Минимальность прав аккаунта остаётся ранее согласованным ограничением.
