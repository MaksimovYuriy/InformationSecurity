# Итерация 1: окружение и основа проекта

> Исторический протокол: названия модулей/тестов и команды приведены на момент этапа. После рефакторинга актуальные структура и запуск описаны в [карте документации](README.md), соответствие имён — в [итерации 10](ITERATION_10.md).

## Проверено в текущей среде

- Python 3.12.8, отдельное виртуальное окружение `.venv`.
- Сначала написаны тесты; первоначальный запуск завершился ожидаемой ошибкой отсутствия реализации.
- После реализации проходят пять тестов: безопасные значения по умолчанию, ошибки конфигурации, права каталогов, консольный запуск и отсутствие секретов в выводе.
- Выполнен отдельный запуск команды проверки в виртуальном окружении.
- Используются переменные окружения; `.env`, виртуальное окружение и локальные данные исключены из Git.
- Логирование настроено через стандартный `logging` с выводом в stderr; файловое логирование пока не требуется.

## Развёртывание на отдельном Linux-сервере — итерация 9

Эти действия перенесены в итерацию 9 и не входят в критерии завершения первой итерации. В текущей среде они не выполнялись. Нужны административный доступ и выбранный сервер.

1. Установить Python 3.12+ с поддержкой `venv`.
2. Создать отдельного непривилегированного пользователя приложения без административных прав.
3. Разместить исходники в каталоге приложения, создать виртуальное окружение по README.
4. Передать конфигурацию через окружение либо закрытый файл `.env` с правами `0600`, принадлежащий пользователю приложения.
5. Указать отдельный каталог состояния через `CLOUD_AUDIT_STATE_DIR`; пользователь приложения должен иметь возможность создать его или владеть им.
6. Выполнить команды проверки и тесты от пользователя приложения.
7. Административный SSH-доступ ограничить доверенными адресами и ключами; проверять действующее подключение перед изменением правил доступа. Порты приложения открывать не требуется: сетевого сервиса пока нет.
8. Не запускать приложение от root. Постоянный процесс и systemd будут нужны при появлении серверного API.

Первая итерация завершена: локальное окружение, структура приложения, безопасная конфигурация и команда проверки подготовлены и проверены. Настройка отдельного сервера, пользователя приложения и сетевых ограничений перенесена в итерацию 9. Переход ко второй итерации допускается; её реализация ещё не начата.
