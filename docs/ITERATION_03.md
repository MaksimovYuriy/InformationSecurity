# Итерация 3: VK Cloud Object Storage

> Исторический протокол: названия модулей/тестов и команды приведены на момент этапа. После рефакторинга актуальные структура и запуск описаны в [карте документации](README.md), соответствие имён — в [итерации 10](ITERATION_10.md).

## Реализовано и проверено

- Адаптер S3 через boto3 с внедрением клиента; SDK остаётся в инфраструктуре.
- Профиль `vk` для `connection` и `resources`, общие настройки для нескольких бакетов.
- Список бакетов обрабатывает continuation token, исключает дубликаты и отклоняет повреждённую пагинацию. До получения всех страниц частичный результат не возвращается.
- HTTPS, Signature V4, path-style, ограниченные тайм-ауты и до трёх попыток SDK.
- Ошибки доступа, авторизации, отсутствующего ресурса, лимитов и сети преобразуются в безопасные сообщения. Исходные ошибки SDK не печатаются; диагностические журналы SDK отключены.
- `audit --profile vk` явно отклоняется: сбор конфигурации и правила относятся к последующим итерациям. Отчёт не создаётся.
- TDD: сначала новый тестовый модуль упал из-за отсутствия `load_s3_settings`, затем добавлена реализация. Полный прогон: 15 тестов успешно, включая Stubber настоящего SDK и CLI.
- 22.11.2026 выполнены два реальных CLI-запуска с локальными ключами: `connection --profile vk` → `status: ok`; `resources --profile vk` → один бакет. Секреты и имена бакетов в протокол не включены. `.env` загружался локальным вспомогательным процессом без вывода значений и без исполнения shell-кода.

## Стенд и воспроизведение

1. Создать отдельный учебный проект VK Cloud в регионе Москва.
2. Создать приватный бакет Hotbox с уникальным именем и небольшими искусственными файлами; объекты также оставить приватными.
3. Отделить учётные данные управления стендом от аудитора. В документации VK Cloud доступ регулируется областью действия ключей, политиками бакетов и ACL; нельзя считать имя аккаунта `reader` ограничением прав.
4. Для текущего адаптера необходима возможность `ListBuckets` (в терминологии AWS — `s3:ListAllMyBuckets`). Нельзя автоматически переносить AWS IAM-политику в VK Cloud: поддержку действий нужно сверять с API провайдера. Чтение ACL и политик пока не требуется и не проверялось.
5. Заполнить `.env` по `.env.example`, права файла `0600`. Не выводить его и не сохранять в Git. Приложение читает окружение процесса, а не файл.
6. Установить зависимости и выполнить команды из README. Сравнить список с личным кабинетом. Не включать публичный доступ для проверки подключения.
7. При удалении стенда отозвать выделенные ключи, удалить искусственные объекты (включая версии и незавершённые multipart-загрузки, если они появились), затем бакеты и ненужный учебный проект. Объекты с блокировкой хранения удаляются по условиям блокировки; для первого стенда блокировку не включать.

## Статус

Адаптер и реальное подключение проверены. **Итерация завершена по решению пользователя от 22.11.2026 с согласованными ограничениями.** Пользователь разрешил продолжать без дополнительного подтверждения прав через интерфейс. Минимальность фактических прав аккаунта и отделение их от прав управления стендом не подтверждены; отдельное пользовательское сопоставление списка с кабинетом также не зафиксировано. Эти пункты приняты как исключение из критериев закрытия текущей итерации, а не как успешно выполненные проверки. Реальный отказ в доступе не создавался: обработка проверена Stubber и тестами, без изменения облачных разрешений.

Регион подписи по умолчанию `us-east-1` успешно использован на московском endpoint; это технический параметр подписи, а не местонахождение бакетов. Реальная многостраничная выдача не наблюдалась, пагинация проверена локально.
