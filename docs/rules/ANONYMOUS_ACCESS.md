# Проверки анонимного доступа

Правила: `anonymous-read`, `anonymous-list`, `anonymous-write`, `anonymous-delete`.

## Угрозы и входные данные

Чтение раскрывает содержимое, список — имена/структуру, запись позволяет загружать и перезаписывать, удаление нарушает доступность. Это разные операции и отдельные проверки. Основные источники: политика бакета, ACL бакета/выбранного объекта, Ownership Controls, доступные настройки Public Access Block и необязательные анонимные пробы.

Для read/write/delete конфигурационный анализ выполняется на явно выбранных ключах; без них возвращается insufficient_data, если нет положительной отдельной пробы. List относится к бакету. Проверки версий объектов, всех префиксов и всего аккаунта в этот охват не входят.

## Поддерживаемый анализ

- Принципал `*`, в том числе AWS:* и списки; конкретные именованные субъекты не считаются анонимными.
- Allow/Deny, строки/списки Action и Resource. `*`/`?` — маски IAM; скобки [] не являются шаблонами оболочки. Action сравнивается без учёта регистра, Resource — с учётом.
- Безусловный применимый Deny имеет приоритет над Allow и ACL.
- В VK Cloud bucket READ разрешает список; object READ — содержимое. Bucket WRITE разрешает загрузку/перезапись и удаление; object FULL_CONTROL не даёт удаления. AuthenticatedUsers не является анонимной группой AllUsers.
- BucketOwnerEnforced отключает использование ACL. IgnorePublicAcls учитывается при наличии доступной настройки. BlockPublicAcls/BlockPublicPolicy сами по себе запрещают изменение настроек, а не доказывают закрытие существующего доступа.
- Condition, NotAction/NotResource/NotPrincipal и незнакомые конструкции не вычисляются. Возможность их влияния отражается как неизвестность с ограничением policy_data_or_conditions_not_resolved; закрытость при этом не утверждается. Разрешение при неизвестных ограничениях даёт потенциальный риск. Известный безусловный Deny конкретной операции остаётся достаточным для запрета в этом конфигурационном контексте.

Публичное разрешение из конфигурации классифицируется как potential_risk: фактическая достижимость ещё не подтверждена. Отсутствие прав/политики или неопределённость, мешающая выводу, — insufficient_data. Passed означает отсутствие анонимного разрешения в поддерживаемой модели для выбранных целей, а не отсутствие всех угроз.

Положительный unsigned-запрос даёт confirmed_violation независимо от предположений конфигурационного анализа: это факт для записанного объекта/операции/момента. Отрицательная проба не закрывает неизвестные условия для других контекстов и не отменяет найденное потенциальное разрешение. HTTP 404, сеть и неверный ответ не считаются доказанным запретом. HTTP 403 AccessDenied — отказ конкретному запросу.

## Доказательства, риск, исключения

В отчёте сохраняются нормализованные входные настройки и метаданные пробы: операция/метод, объект, HTTP-статус, время, результат. Содержимое объекта, списки имён из ответа ListObjects и учётные данные не сохраняются. Положительная проба повышает likelihood до 3; остальная модель риска v1 сохраняется. Риск остаётся экспертной оценкой последствий, а не измеренной вероятностью. Принимаемые исключения по бакету/правилу сохраняют статус, риск и доказательства с причиной.

## Подтверждение и исправление

Удалить непредусмотренные анонимные Allow и гранты AllUsers для нужной операции. Проверить ACL объектов отдельно от ACL бакета. Повторно собрать конфигурацию и выполнить unsigned-запрос на том же искусственном объекте или списке. Исправление подтверждается отказом этого запроса и новым результатом анализа; оно не распространяется автоматически на все объекты/контексты.

Пробы чтения запрашивают Range bytes=0-0 и закрывают поток после не более одного байта. Список запрашивается с MaxKeys=1. Запись/удаление — только с --allow-write-probes вместе с --probe-anonymous, на новых условно создаваемых ключах в `_cloud-audit-probe/<uuid>/`, с проверкой отсутствия предшествующих версий и уборкой версий/маркеров. Подтверждение отсутствия Object Lock и возможность перечисления версий требуются для подготовки. Ошибка уборки явно сохраняется как cleanup_failed и делает оценку incomplete.
