# Сканирование хранилища: что проверяется, как и почему

## Охват

Один запуск работает с одним выбранным бакетом VK Cloud S3. Наличие многих бакетов не требует новых переменных: endpoint/ключи общие, ресурс задаётся аргументом. Пакетного сканирования всех бакетов нет. Все объекты и версии автоматически не обходятся.

Без флагов собираются восемь настроек бакета. `--objects` добавляет ACL до 20 уникальных явно выбранных ключей, каждый до 1024 байт. Содержимое пользовательских файлов в снимок или отчёт не сохраняется.

| Наблюдение | API | Для чего |
|---|---|---|
| bucket_acl | GetBucketAcl | Владелец, групповые и именованные гранты |
| bucket_policy | GetBucketPolicy | Action/Resource/Principal/Effect и исходные условия |
| public_access_block | GetPublicAccessBlock | В частности IgnorePublicAcls; неподдержка API не доказывает отсутствие защиты |
| ownership_controls | GetBucketOwnershipControls | Действуют ли ACL |
| versioning | GetBucketVersioning | Восстановление после перезаписи/удаления в пределах настройки |
| logging | GetBucketLogging | Факт настройки, пока без самостоятельного обязательного правила |
| encryption | GetBucketEncryption | Настройка по умолчанию, без вывода о каждом объекте |
| object_lock | GetObjectLockConfiguration | Факт блокировки; мутационные пробы требуют подтверждённого отсутствия |
| object_acl:KEY | GetObjectAcl | ACL только выбранного объекта |

Полный порядок обработки: нормализация → снимок → движок → находки/риск → отчёт. Настройки коллектора не являются отдельными правилами безопасности. Выбранные восемь правил обоснованы в [каталоге](rules/RULE_CATALOG.md); карточки дополняют описание ниже.

## Статусы и доказательства

- `confirmed_violation`: установленное нарушение baseline или успешная анонимная операция; это разные виды подтверждения, указанные в evidence.
- `potential_risk`: риск по конфигурации, без утверждения о фактическом доступе субъекта.
- `passed`: в выбранном охвате правило не обнаружило нарушения; не заключение о всём бакете.
- `insufficient_data`: фактов/контекста недостаточно; риск unknown, общий отчёт incomplete.
- `not_applicable`: алгоритм неприменим к данному охвату.

Наблюдения отдельно различают available, absent, access_denied, unsupported, error и not_found. Ошибка чтения не превращается в отсутствие настройки. Движок проверяет required_data: при недоступности обязательного источника правило не исполняется. Анонимные и инвентаризационные правила сами объединяют источники, чтобы недоступный необязательный факт не скрыл положительное доказательство.

## Восемь правил

### bucket-versioning-enabled

**Зачем:** снизить риск необратимой перезаписи/удаления. Источник — versioning.status, не политики доступа.

Enabled → passed. Disabled/Suspended → confirmed_violation, если `versioning` входит в required_controls; иначе potential_risk. Недоступное/нераспознанное значение → insufficient_data. Пустой успешный S3-ответ означает Disabled; неизвестный MFADelete остаётся null.

**Исправление:** включить версионирование, если оно требуется политикой восстановления. **Подтверждение:** свежий GetBucketVersioning с Enabled и повторный аудит; восстановление файла проверить отдельно. Контроль не доказывает резервное копирование и не возвращает ранее утраченные версии. [Карточка](rules/BUCKET_VERSIONING.md).

### anonymous-read

**Зачем:** обнаружить чтение данных посторонним. Цели — только выбранные ключи, Action GetObject, Resource — точный объект ARN. ACL — READ/FULL_CONTROL у AllUsers на объекте, не bucket READ.

Успешный unsigned GET → confirmed_violation. Безусловный публичный Allow или применимый ACL без положительной пробы → potential_risk. Неизвестные условия/недоступный ACL не доказывают закрытость. Нет выбранных объектов → insufficient_data. Неприменимые ACL при Enforced или IgnorePublicAcls игнорируются.

**Исправление:** убрать непреднамеренные публичные Allow и объектные AllUsers-гранты. **Подтверждение:** новый unsigned GET того же искусственного объекта с HTTP 403 после изменения и повторный аудит.

### anonymous-list

**Зачем:** обнаружить раскрытие списка ключей. Цель — ARN бакета, Action ListBucket; bucket READ/FULL_CONTROL у AllUsers разрешает список. Object READ не разрешает список бакета.

Положительный unsigned ListObjectsV2 → confirmed_violation; публичная настройка без подтверждения → potential_risk; неразрешимая конфигурация → insufficient_data. Выбор объектов для этого правила не обязателен.

**Исправление:** убрать публичный ListBucket и bucket AllUsers READ. **Подтверждение:** новый анонимный список получает HTTP 403.

### anonymous-write

**Зачем:** обнаружить возможность загрузки посторонних данных. Статический Action PutObject сопоставляется выбранным объектным ARN; в модели VK bucket WRITE/FULL_CONTROL включает запись. Для статического анализа без выбранных целей возможен insufficient_data.

Успешный unsigned PUT на новом специально созданном probe-ключе → confirmed_violation. Явное публичное разрешение без положительного запроса → potential_risk. Риск не является доказанным случаем изменения пользовательских файлов.

**Исправление:** убрать публичный PutObject/bucket WRITE, сохранить нужные права приложений. **Подтверждение:** отдельная согласованная проба на искусственной цели. Обычный аудит без двух флагов записи не выполняет PUT.

### anonymous-delete

**Зачем:** обнаружить возможность уничтожения данных. Action DeleteObject; bucket WRITE в VK также разрешает удаление. Object FULL_CONTROL не считается разрешением удаления объекта.

Успешный unsigned DELETE подготовленного probe-объекта → confirmed_violation; настройка без пробы → potential_risk. Предварительная загрузка и уборка выполняются подписанным клиентом только на собственном UUID-ключе.

**Исправление:** убрать публичный DeleteObject/bucket WRITE. **Подтверждение:** ограниченная искусственная проба и повторный сбор. Все версии/сценарии удаления этим не проверяются.

Общие источники и ограничения четырёх операций: [ANONYMOUS_ACCESS.md](rules/ANONYMOUS_ACCESS.md).

### unapproved-external-access

**Зачем:** найти явные права субъектов вне допустимого круга. Инвентарь разворачивает поддерживаемые ACL и Allow/Deny-политики на выбранные бакет/объекты. AllUsers/Principal * относятся к анонимным правилам; AuthenticatedUsers — группа внешнего аутентифицированного доступа.

Владелец бакета по ACL, trusted_project_ids и allowed_external_accounts учитываются отдельно. Владелец произвольного объекта не становится доверенным для всего бакета. Проектный ID может покрывать user ARN своего проекта; неизвестные формы Principal и условия отмечаются ограничениями.

Неутверждённый явный грант → potential_risk. Нет гранта, но есть неизвестность/нет собственного проектного контекста → insufficient_data. Иначе passed только для явных грантов этого охвата. Действующие учётные данные внешнего пользователя не используются.

**Исправление:** удалить непреднамеренный грант либо явно утвердить субъект после проверки потребности. **Подтверждение:** новый снимок с заданным контекстом доверия; фактический вход субъекта проверить отдельно.

### excess-explicit-permissions

**Зачем:** сравнить права с необходимыми операциями, заданными пользователем. `required_permissions` содержит точный subject и operations. Пустой operations — явное требование отсутствия прав; отсутствие всей baseline — недостаток данных.

Для каждого субъекта учитываются покрывающие его гранты и подходящие Deny. Наблюдаемая операция вне baseline → potential_risk. Если превышения не видно, но субъект не наблюдался, контекст проекта неизвестен, действия не отображены или возможны внутренние implicit-права → insufficient_data. Иначе passed в пределах явных операций. Недостающий приложению доступ правило не ищет.

Поддерживаемые операции: read, list, write, delete, read_acl, write_acl, read_policy. FULL_CONTROL раскрывается по контексту bucket/object; маски раскрываются только в этой конечной модели, не считаются полным IAM.

**Исправление:** сузить Action/Resource/ACL до подтверждённой потребности приложения. **Подтверждение:** повторный анализ с той же baseline и отдельная проверка нужных действий. Текущие права не копируются автоматически в желаемые.

### bucket-acl-disabled

**Зачем:** снизить вероятность случайного открытия через ACL. Источник — Ownership Controls.

BucketOwnerEnforced → passed. BucketOwnerPreferred/ObjectWriter → potential_risk, а при обязательном `acl_disabled` → confirmed_violation baseline. Неизвестное значение → insufficient_data. Включённые ACL сами по себе не доказывают публичного гранта, а выключенные не блокируют публичную политику.

**Исправление:** проверить совместимость приложений, перенести необходимые разрешения в политики и отключить ACL. **Подтверждение:** свежие Ownership Controls, повторные анонимные проверки и проверка приложений. [Карточки управления доступом](rules/GOVERNANCE_ACCESS.md).

## Правила интерпретации политик и ACL

Поддерживаются подходящие Effect/Principal/Action/Resource, строки и списки, маски * и ? с IAM-семантикой. Безусловный релевантный Deny приоритетнее Allow/ACL. Condition, NotAction, NotPrincipal, NotResource не вычисляются и сохраняют неизвестность. Неизвестный запрет не становится доказанным отказом. Подтверждённый unsigned-доступ приоритетнее предположений по конфигурации.

IgnorePublicAcls применяется к публичным группам, а не ко всем именованным ACL. BucketOwnerEnforced выключает ACL. Доступные настройки BPA рассматриваются в пределах реализованных алгоритмов; блокировка создания новых публичных настроек не подменяет проверку уже существующих разрешений.

## Независимые запросы и безопасные пробы

`--probe-anonymous`: отдельный клиент UNSIGNED с пустыми credentials, path-style, тайм-ауты 5/10 с и одна попытка. Выполняется список MaxKeys=1 и GET Range bytes=0-0 каждого выбранного ключа. Body читается максимум на один байт и закрывается, содержимое не сохраняется. 2xx → allowed; только AccessDenied/403 → denied; 404 → not_found, не доказательство закрытия; сеть/неверный ответ → error.

`--allow-write-probes` требует также `--probe-anonymous`, свежего vk-ресурса, подтверждённого отсутствия Object Lock и прав подготовки/уборки. Ключи только `_cloud-audit-probe/UUID/write.txt` и `delete.txt`. До изменения перечисляются версии точного ключа; существующие цели/неполное перечисление отклоняются. PUT использует IfNoneMatch='*'. Уборка перечисляет и удаляет только точные версии/маркеры созданных целей. Сбой уборки сохраняет положительное доказательство, добавляет cleanup_failed и делает отчёт incomplete. Для живого стенда положительные write/delete не проверялись.

## Риск и исключения

Impact: low=1, medium=2, high=3, unknown=2. Likelihood: 3 при подтверждённом unsigned-доступе, иначе 2. Score=impact×likelihood. Уровни: 9 critical, от 6 high, от 3 medium, иначе low. Passed/not_applicable: none/0; insufficient_data: unknown/null. Это порядковый приоритет, не измеренная вероятность инцидента; оценка не моделирует стоимость данных и все средства восстановления.

Исключение применяется только к найденному нарушению/риску, к точным resource_id/rule_id и до expires_at. Срок проверяется относительно сбора и текущего времени оценки. Статус, риск и доказательства сохраняются, добавляется exception_reason. Исключение не превращает insufficient_data в passed и не скрывает находку в сравнении.

## Подтверждение исправления

Нужны новый снимок с более поздним collected_at, одинаковые mode/resource.id/известный namespace, версия правил, охват и выбранные объекты, одинаковая baseline (кроме исключений). Переход находка→passed тогда может быть resolved. Для подтверждённого анонимного доступа дополнительно нужны новые denied/403 по всем ранее allowed-целям с временем позже положительных запросов.

Пропущенное правило, недостаток данных, failed-run, изменённый охват или неизвестный provenance не доказывают исправление. Генерируемые write/delete-цели обычно меняются: отсутствие совпадения даёт unverified, а не автоматическое resolved. Повторный анализ одного снимка не доказывает новое нарушение или исправление.

Реальная проверка read/list и фиксированная матрица: [ACCEPTANCE_MATRIX.md](ACCEPTANCE_MATRIX.md). Ограничения не означают, что эти возможности уже реализованы.
